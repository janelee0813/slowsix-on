# 스페이스클라우드 직접 연동 설정

Supabase에 예약 처리 대기 목록을 저장하고, Vercel이 요청이 있을 때만 브라우저를 실행합니다. PC를 켜둘 필요가 없습니다. 공집사를 이용하지 않습니다. Vercel·Supabase 사용량은 현재 요금제 한도에 포함되므로 추가 요금이 항상 0원이라고 보장하지는 않습니다.

현재 상태: 코드와 로컬 테스트 준비 완료. 실제 스페이스클라우드 서버에서 로그인·등록·삭제까지의 검증은 아직 하지 않았습니다. 아래 설정을 완료한 뒤 테스트를 먼저 진행해야 합니다. 자동 연동은 기본적으로 꺼져 있습니다.

## 1. Supabase SQL 실행

프로젝트 qhvwwdrwfzwpehfjntbv → SQL Editor → New query에서 `01-update.sql` 전체를 붙여 넣고 Run을 누릅니다. 기존 멤버십이 설치된 프로젝트에 적용합니다. 쿠폰 업데이트(007)와 연동 업데이트(008)를 포함하며 기존 계정·예약·정산 내역은 유지합니다.

## 2. admin-api 업데이트

Supabase → Edge Functions → admin-api → Code에서 `02-admin-api.ts` 전체로 교체하고 Deploy updates를 누릅니다. 기존 Secrets와 JWT 설정을 유지합니다. SPACECLOUD_ICAL_UID도 유지해주세요.

## 3. 자동 실행 설정

SQL Editor 새 쿼리에서 `03-scheduler.sql`을 실행합니다. 결과로 나온 `SPACECLOUD_SYNC_SECRET` 값을 다음 단계에서 복사해서 사용합니다. 이 값은 비밀값이므로 채팅에 보내지 않습니다. 스케줄러는 매분 대기 작업을 확인하고, 새 작업이 있으면 즉시 실행을 요청합니다. 처리할 작업이 없으면 브라우저는 실행하지 않습니다.

## 4. Vercel 환경변수 설정

슬로우식스온 프로젝트 → Settings → Environment Variables에서 아래 4개를 Production 환경에 추가합니다.

| 이름 | 넣을 값 |
|---|---|
| SPACECLOUD_EMAIL | 스페이스클라우드 호스트 이메일 |
| SPACECLOUD_PASSWORD | 스페이스클라우드 호스트 비밀번호 |
| SPACECLOUD_SYNC_SECRET | 3번 SQL 결과값 |
| SUPABASE_SERVICE_ROLE_KEY | 같은 Supabase 프로젝트의 service_role 키 |

service_role 키는 Supabase 프로젝트 Settings → API Keys의 legacy service_role 키입니다. 기존 anon/public 키와 다릅니다. 키와 비밀번호는 Vercel 환경변수에만 직접 입력하고 채팅이나 GitHub 파일에 적지 않습니다. Vercel Deployments에서 최신 배포의 Redeploy를 실행합니다. Node.js 22와 실행 시간 180초 설정이 코드에 포함돼 있습니다.

## 5. 설정 완료 후 테스트

여기까지 완료하면 Codex에 설정 완료라고 알려주세요. 실제 예약이 없는 시간 한 구간을 정해 등록·차단·해제를 확인한 뒤 자동 연동을 켭니다. 지금은 켜지 마세요. 테스트 전에 실제 예약 시간을 변경하지 않았습니다.

관리자 모드 → 멤버십 관리 → 스페이스클라우드 연동에서 상태를 확인할 수 있습니다. 서버 설정 후 최근 서버 확인 시각이 나타납니다. 이 시각은 실행 서버 연결 확인이며 스페이스클라우드 로그인 성공을 의미하지는 않습니다.

## 동작 기준

- ON 공간(space=79746, product=133597)에만 적용합니다.
- 008 설치 이후 들어온 예약 요청부터 대기 목록에 기록합니다. 기존 예약은 자동으로 일괄 등록하지 않으며 필요한 예약의 '스클 일정 연동' 버튼으로 추가합니다.
- 예약 요청·입금 대기·확정 상태는 차단 대상, 거절·취소는 해제 대상입니다.
- 스클 등록 이름은 SSO-로 시작하는 예약 식별값을 사용합니다. 회원 이름·연락처는 전송하지 않습니다.
- 자정을 넘는 예약은 날짜별로 나눠 등록합니다. 같은 식별값·날짜·시간이 이미 있으면 재등록하지 않습니다.
- 삭제는 해당 예약 식별값과 날짜·시간·메모가 모두 일치하는 직접 추가 일정에만 시도합니다. 일반 스클 예약이나 다른 외부 일정은 삭제하지 않습니다.
- 실행 중 취소되면 현재 실행을 마친 뒤 차단 해제를 처리합니다. 실행 중단·부분 처리·화면 변경 등 결과가 불확실하면 확인 필요 상태로 남깁니다.
- 로그인 실패 시 자동 연동을 끕니다. 반복 로그인으로 계정이 잠기지 않도록 로그인 정보를 확인한 뒤 다시 켜야 합니다.
- 외부 시스템에서 같은 순간 예약이 들어오는 경우를 완전히 원자적으로 차단할 수는 없습니다. 스클 차단 완료를 확인하고 승인·입금 안내를 진행합니다.
- 사이트 내 예약 거절·취소와 환불은 별도입니다. 연동은 일정만 다룹니다.

자동 연동을 끄면 기존 스클 차단은 유지됩니다. 꺼진 동안 취소한 일정은 직접 해제하거나 연동을 다시 켜서 처리해야 합니다.
